# G1 · 餐桌残留检测 · Video Prompt

> 规则编码：G1 | 优先级：P2（实验规则）
> 对应 MVP §4.2 实验规则 | 检测目标：顾客离席后餐桌上的食物残渣、餐具未收、纸巾/垃圾遗留
> **复杂度最高**：需同时处理餐具、食物残渣、纸巾、杯具等多类目标的混叠与状态判定

---

## 通用参数（所有样本共用）

| 参数 | 值 | 说明 |
|------|-----|------|
| 分辨率 | 1080×1920 | 竖屏 9:16 |
| 帧率 | 30 fps | |
| 时长 | 主样本 10-15s / 负样本 5-8s / 边界 8-12s | 实验规则可适当延长，覆盖「顾客离席 → 桌面状态」完整时序 |
| 风格 | 真实监控摄像头风格 | 固定机位、无滤镜、轻微噪点 |
| 参考图 | `./artifacts/user_photo_20260927.jpg` | 保持门店装修风格一致 |

### 平台限制提醒

- 豆包/可灵/海螺：单段 ≤ 10s；G1 需要时序连续性，建议用多段拼接或控制在 10s 内覆盖关键帧
- Minimax：单段 ≤ 5s，不建议用于 G1（时序太短）
- **建议**：使用豆包或可灵，单段 10s 内包含「顾客起身离席 → 桌面残留暴露」的完整过程

> ⚠️ **最高复杂度规则**：需同时识别「顾客已离席」（人检）+「桌面有残留物」（物检）+「残留物类型/数量」（分类），三者叠加。

## 主样本 Prompt（Positive）

### G1-POS-01 · 典型餐后残留（奶茶杯 + 食物残渣 + 纸巾）

```
固定监控摄像头视角，竖屏 9:16，俯视 slightly 斜视门店大厅的一张四人餐桌。
画面开始时，两名顾客坐在桌旁，桌上有两杯喝完的奶茶（杯中有少许残余液体和珍珠），一个空甜品碗（碗边有奶油残留），几张用过的纸巾揉成团散落在桌面，一根用过的吸管包装纸。
约 3 秒后，两名顾客起身离开，椅子被稍微推开。
顾客离席后，桌面上的所有残留物清晰可见：奶茶杯×2、甜品碗×1、纸巾团×3、吸管包装×1、桌面有几滴洒落的奶茶渍。
桌面无人员，背景有其他顾客在远处座位区。
真实监控画质，固定机位，白天自然光+室内灯，画面明亮清晰。
```

**标注要点**：
- event_type: `table_residual`
- sub_types: `cup` / `bowl` / `tissue` / `wrapper` / `spill`
- bbox: 整张餐桌区域 + 各残留物细分类 bbox
- severity: `minor`
- 注意：顾客已离席的判定（人物检测 + 时序消失）

## 边界 Case Prompt（Edge）

### G1-EDGE-01 · 仅一个空杯（极简残留）

```
固定监控摄像头视角，竖屏 9:16，俯视双人桌。
顾客离席后，桌上只有一个干净的空奶茶杯（杯盖盖好，无液体残留），无其他物品。
杯子摆放整齐，桌面整体干净。
真实监控画质，固定机位，白天。
```

**标注要点**：confidence_gt = 0.50，一个空杯是否算「残留」？——取决于业务定义（建议：空杯不算，开盖/有残液才算）

```
A 桌顾客离席，桌上有两个奶茶杯。B 桌顾客仍在座，其中一名 B 桌顾客伸手拿起 A 桌的一个杯子（可能是同行人）。
```

**标注要点**：confidence_gt = 0.60，跨桌物品转移的时序理解，考验模型的动作/关联推理能力

### G1-EDGE-03 · 桌面有水渍但无实物残留

```
固定监控摄像头视角，竖屏 9:16，俯视餐桌。
顾客离席后，桌面干净无任何杯具/纸巾/食物，但有几滴圆形水渍（直径 1-2cm，约 3-4 滴）。
```

**标注要点**：confidence_gt = 0.45，水渍是否算「残留」？——建议：纯水滴不算，有色/有质液体算

## 双层判定对接说明

| 层级 | 触发条件 | 处理方式 |
|------|----------|----------|
| **Layer 1** | 所有样本过 Layer 1 | Vision 输出 `table_residual` / `clean` + 置信度 + 残留物列表（类型/数量/位置） |
| **Layer 2** | confidence 0.50-0.80 或残留物种类复杂/混叠严重 | 抽帧 → 放大桌面区域 → 二次判定各残留物类型和数量 + 确认顾客是否已离席 |
| **后端规则** | 两阶段阈值验证（见下方「阈值验证策略」） | 触发告警，生成 evidence.json；残留物数量 ≥ 5 或面积 > 30% 桌面升级严重度 |

> **关键复杂度**：G1 是 MVP 中唯一需要「人物检测 + 物品检测 + 时序理解 + 状态分类」四重叠加的规则。

---

## 阈值验证策略（两阶段）

> ⚠️ **原阈值 120 秒已废弃**，改为两阶段验证，适配不同长度测试视频。

### 阶段 1：短视频边界测试（≤ 50s）

- **目的**：验证模型在短视频边界条件下的判定稳定性，避免「视频时长不足但模型强行触发」的误报。
- **主样本设计**：0–50s 短视频中，顾客离席后桌面残留持续 **35s**（< 60s 阈值）→ **预期不触发告警**。
- **判定逻辑**：`顾客离席确认` + `残留物识别` + `持续时间 35s` → 因 35s < 阶段 1 阈值 60s，**后端规则不触发**。
- **通过标准**：模型输出 `table_residual` 置信度可正常输出，但后端规则过滤后 **evidence.json 中 trigger = false**。

### 阶段 2：完整时长阈值验证（≥ 10min，留待 Phase 2）

- **目的**：在真实长视频（完整营业时段）中验证「持续未清理」的累积触发逻辑。
- **视频要求**：≥ 10 分钟的固定机位监控录像，覆盖「顾客离席 → 残留暴露 → 长时间未收」的完整过程。
- **阈值定义**：顾客离席后桌面残留 **持续 ≥ 120s 未清理** → **触发告警**。
- **判定逻辑**：`Layer 1 检出残留` → `Layer 2 确认顾客已离席` → `后端计时累积 ≥ 120s` → **evidence.json 中 trigger = true**。
- **时间戳记录**：记录 `customer_left_at`（顾客离席时间）和 `alarm_triggered_at`（告警触发时间），差值 ≥ 120s。

### 阈值对照表

| 阶段 | 视频长度 | 测试目的 | 阈值 | 预期触发 | 状态 |
|------|----------|----------|------|----------|------|
| 阶段 1 | ≤ 50s | 边界 case 验证（防止短视频误报） | 60s | 35s 残留 = **不触发** | **本版本已启用** |
| 阶段 2 | ≥ 10min | 真实场景累积触发验证 | 120s | ≥ 120s 残留 = **触发** | **留待 Phase 2 长视频测试** |

### 与旧版差异

- **旧版**：统一阈值 120s，不区分视频长度，导致 50s 测试视频中「35s 残留被误触发」。
- **新版**：阶段 1 用 60s 阈值做边界保护，阶段 2 用 120s 阈值做真实场景累积判定，两层互补。
