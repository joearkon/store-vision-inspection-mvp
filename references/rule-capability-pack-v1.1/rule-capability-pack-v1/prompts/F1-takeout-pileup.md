## 主样本 Prompt（Positive）

### F1-POS-01 · 取餐台严重堆积（高峰期）

```
固定监控摄像头视角，竖屏 9:16，俯视 slightly 斜视门店取餐区/出品台。
取餐台长约 1.5 米，不锈钢台面，上方有取餐叫号屏。
台面上堆满了已制作完成的奶茶杯（约 15-20 杯），摆放杂乱无章，无固定分区。
杯子相互紧挨，有的倾斜，有的杯盖未完全扣紧。
部分杯子无订单标签或小票，无法辨认归属。
两名顾客站在取餐台前，面露困惑，正在翻找自己的订单。
背景可见门店大厅，有其他顾客排队等候。
真实监控画质，固定机位，白天，顶灯照明。
```

**标注要点**：
- event_type: `takeout_pileup`
- bbox: 取餐台区域 + 堆积物区域
- severity: `major`
- 注意：堆积数量、摆放整齐度、是否有标识/标签、顾客困惑程度

## 负样本 Prompt（Negative）

### F1-NEG-01 · 规范摆放的取餐区

```
固定监控摄像头视角，竖屏 9:16，俯视取餐台。
取餐台整洁有序，已完成的订单按编号顺序整齐排列。
每个杯子/碗旁都有清晰的小票标签，标明订单号和内容。
取餐台分为「待取区」和「已完成区」，有清晰的标识牌。
台面空余空间充足，新订单有固定放置位置。
一名顾客快速找到自己的订单并取走，过程顺畅。
真实监控画质，固定机位，白天。
```

**关键区分点**：规范分区 + 清晰标识 + 有序排列 + 顾客取餐顺畅

## 边界 Case Prompt（Edge）

### F1-EDGE-01 · 数量多但摆放整齐

```
固定监控摄像头视角，竖屏 9:16，俯视取餐台。
取餐台上有约 12-15 个已完成订单，数量较多。
但所有订单都按编号顺序排列整齐，每个都有清晰标签，分区明确。
顾客能快速定位自己的订单，无翻找或困惑行为。
真实监控画质，固定机位，白天。
```

**标注要点**：confidence_gt = 0.55，数量多但摆放整齐是否算「堆积混乱」？——建议：以「是否影响取餐效率/导致错拿」为核心判定标准，非单纯数量

## 双层判定对接说明

| 层级 | 触发条件 | 处理方式 |
|------|----------|----------|
| **Layer 1** | 所有样本过 Layer 1 | Vision 输出 `takeout_pileup` / `organized` + 置信度 + 取餐台 bbox |
| **Layer 2** | confidence 0.55-0.85 | 抽帧 → 放大取餐台区域 → 二次判定堆积密度、标签清晰度、分区状态 |
| **后端规则** | Layer 2 确认堆积且持续 ≥ 120s 或顾客翻找/困惑行为明显 | 触发告警；溢出到地面或堆叠直接 Major |
