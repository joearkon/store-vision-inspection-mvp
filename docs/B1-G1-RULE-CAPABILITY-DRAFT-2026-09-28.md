## 2. B1：烟雾 / 异常明火

### 模型只判断可见事实

单帧状态：`clear_smoke`、`clear_flame`、`steam_or_cooking_vapor`、`none`、`unknown`。返回画质、设备 ROI、烟/火位置、来源是否可见、置信度和可复核的简短证据。无法确认是烟还是蒸汽时输出 `unknown`，不得输出“起火原因”或“电器故障”等画面外推断。

### 后端状态机（待评审参数）

```text
无异常
  → 高置信度首帧 clear_smoke / clear_flame：P0 疑似预警（独立于已确认事件）
  → 后续 2 个有效观察帧继续命中同一 ROI：升级为 P0 确认事件
  → 后续帧为 steam_or_cooking_vapor、none 或证据不足：保留首帧审计，撤销/待人工复核，不生成“已确认”
  → 异常消失：记恢复证据，事件不自动关闭，由人工完成处置审计
```

首帧阈值、复核帧间隔、连续性窗口和蒸汽排除条件由后端配置；P0 预警与 P0 确认使用同一事件链，避免重复告警。测试阶段 `notifications_enabled=false`，通过页面/数据库核对后再做一次受控飞书演练。真实门店不得因为合成烟雾样本通过就自动启用 P0 飞书。

双层模式要保留高危优先级：粗筛一旦发现候选，在候选前后抽足够密的关键帧；视频模型未发现候选但画质不合格时返回“不足以判断”，不能记为无烟。

## 3. G1：餐桌桌面清理（实验规则）

G1 不是“桌上有杯子”规则，也不是“座位空了”规则。必须按**同一张桌子的时序**判断：顾客确实离席、残留物仍在、没有员工正在清理、超过允许的清理等待时间。至少要有 `table_roi_id`；若镜头里有多桌，不能用整张画面合并。

### 每个桌面 ROI 的可见状态

| 状态 | 判定含义 | 是否计时/告警 |
| --- | --- | --- |
| `occupied` | 顾客仍在桌旁就餐或暂时起身但所属关系未消失 | 不计时 |
| `vacated_candidate` | 顾客离开座位；是否真正离席尚不确定 | 等待确认，不计超时 |
| `vacant_with_residue` | 桌位明确无人、杯盘/食物残留可见 | 从确认离席时开始计时 |
| `cleaning_in_progress` | 员工接近并正在收杯盘/擦拭 | 暂停异常确认；保留过程证据 |
| `cleaned` | 桌面残留已清除 | 记录恢复，不产生新事件 |
| `unknown` | 遮挡、离开画面但可能仍在店内、桌面像素不足、灯光变化 | 不强判；连续性可中断 |

### 业务事件条件

```text
同一桌 ROI 已确认 vacated
  ∧ 桌面有可见残留
  ∧ 未观察到 cleaning_in_progress / cleaned
  ∧ 持续达到服务端配置的清理等待阈值
→ G1 待人工复核事件
```

**建议仅用于合成样本的测试阈值：20 秒**，因为现有正片约第 5–7 秒离席、总时长 50 秒；该值不是门店运营 SLA。真实门店的清理时限应由业务负责人确认，暂以 `production_threshold = 未定` 保存，不得把 20 秒测试阈值默认部署到正式门店。G1 先作为实验观察，默认 P2 / 不推飞书 / 不自动归责；严重度也需业务评审。顾客返回、桌面从未有残留、员工在阈值前清理、人员遮挡无法分辨时均不得生成已确认事件。

### 所需产品交互

- 摄像头管理中新增餐区摄像头与逐桌 ROI，显示 ROI ID/名称；没有 ROI 不允许提交 G1 正式分析。
- 上传页只在选中餐区摄像头时显示 G1 实验规则，明确标注「不发飞书、仅供验证」。
- 事件详情显示离席、残留确认、开始清理、清洁完成的时间轴及对应原视频标记。没有清洁完成证据时写「未观察到」，不能写「未清理」。
- 规则能力页明确显示「设计待审 / 实验可用 / 正式」三种真实实现状态，不能以设计稿状态冒充后端可执行状态。

## 4. 双层分析与成本护栏

每条规则各有粗筛 prompt 和精查 schema，不能把 E1 的“门开/关”prompt 改几个字复用。先用视频粗筛定位候选窗口，再对窗口前后精查；关键帧抽样覆盖候选开始、确认阈值、候选结束和视频尾部，以免重复 E1 已发现的“恢复漏记”。`unknown` 不当负样本；模型返回的证据与置信度属于观察层，后端独立完成阈值、事件、严重度、SLA 与通知判定。

每次任务显示并存储：规则版本、prompt 版本、模型接入点 ID、请求数、输入/输出 Token、估计费用与失败重试。先定单视频请求/Token 上限，超限则暂停并显示预计新增消耗，不自动切逐帧基线。合成测试仍关闭飞书。

## 5. 可执行验收矩阵

| 素材 | 期望 | 门槛 |
| --- | --- | --- |
| E1 短开门 50 秒 | 0 事件 | 已通过一次真实双层分析；需保留为回归测试 |
| E1 超时后关门 50 秒 | 1 事件，30 秒确认，关门后记录恢复 | 已确认事件，但恢复未通过；修复后复验 |
| B1 持续烟雾 30 秒 | 疑似预警 → 确认；同一次烟雾只 1 事件 | 后端状态机和模型双层均需通过 |
| B1 正常后厨 30 秒 | 0 事件 | 不可把普通热气误判为烟雾 |
| B1 可见蒸汽 10 秒 | 不生成已确认 P0，必要时人工复核 | 压力负样本；目前仅短片 |
| G1 顾客离席后残留 50 秒 | 在测试阈值下 1 条实验观察 | 必须绑定逐桌 ROI；末帧冻结不计真实时序准确率 |
| G1 顾客仍在座 50 秒 | 0 事件 | 不得仅凭桌面有杯子触发 |
| G1 离席后及时清理（待补视频） | 0 超时事件，记录清理/完成状态 | 现有样本不能验证“清理”能力 |
| G1 离席后返回（待补视频） | 0 事件或取消候选 | 防止把短暂起身误报为离席 |

每组都检查：模型帧观察、后端聚合、事件证据、原视频时间轴、任务失败、请求/Token、飞书开关。只有对应正负样本均通过且人工复核证据后才可改变页面实现状态。
