- 未接入真实监控画面时明确显示“等待接入视频画面”，不伪装直播。

## 2. 自动化测试审计

执行入口：

```powershell
./scripts/verify.ps1
```

当前覆盖：

- API 健康检查与初始化数据。
- 非 MP4 上传拒绝。
- MP4 上传与持久化任务创建。
- 缺失事件返回 404。
- E1 短暂开门不产生事件。
- E1 达到阈值仅创建一个事件。
- 关闭后记录恢复。
- 两次独立开门产生两个事件。
- 证据不足帧不被当作恢复。
- 观察帧间隔过大时重置连续时间。
- 使用 FFmpeg 合成视频完成“视频→抽帧→测试视觉提供器→聚合→事件→证据”集成测试。
- 前端状态文案、持续时间与置信度格式测试。
- 前端生产构建。

测试视觉提供器只用于自动化测试，它通过依赖注入验证管线，不会成为产品运行时的假 AI 回退路径。正式 Worker 在未配置豆包密钥时会明确失败。

## 3. 产品逻辑审计

| 审计项 | 结论 | 说明 |
|---|---|---|
| 是否把单帧观察直接当事件 | 通过 | `FrameFinding` 与 `InspectionEvent` 分离 |
| 是否统一三帧确认 | 通过 | E1 使用持续30秒策略 |
| 同一持续异常是否爆炸式建事件 | 通过 | 一段连续开启聚合为一个候选事件 |
| 是否记录异常恢复 | 通过 | 保存 `recovered_offset` 与恢复证据 |
| 超时是否错误建模为业务状态 | 通过 | 超时由 `due_at` 动态计算 |
| 模型是否决定严重度/SLA | 通过 | E1 严重度与SLA由服务端固定映射 |
| 演示循环是否默认推送 | 通过 | 新任务通知开关默认关闭 |
| 飞书是否有发送幂等 | 通过 | `event_id + confirmed + escalation level` |
| 误报是否删除原记录 | 通过 | 使用终态并保留事件与操作日志 |
| 未接入能力是否伪装可用 | 通过 | RTSP 与实时画面明确标注未接入 |

## 4. 视觉审计

已在 1280×720 视口人工核对：

- 应用框架与原型一致：232px 深色导航、60px 顶栏、浅灰工作区。
- Dashboard 保留四指标卡、2×2 监控矩阵和右侧事件流。
- 主色、危险色、成功色、边框、圆角和字体层级沿用视觉契约。
- 上传页面保持原型的双栏结构、上传区、区域卡片和右侧步骤进度。
- 使用 SVG 线性图标，不使用 emoji 作为正式图标。
- 页面切换保留约250ms轻微淡入位移动效。

仍需在有真实事件数据后补充：事件详情、长异常描述、失败任务、超时和证据图的截图回归。

## 5. 未通过的最终门禁

以下项目不应被描述为“已完成”：

1. 尚未使用用户的火山引擎密钥运行真实视频。
2. 尚未确认模型 Endpoint/Model ID 与账号资源一致。
3. 尚未使用真实飞书机器人发送卡片。
4. 尚未取得满足 E1 场景的正式验收视频。
5. 当前只有初始化账号，尚未实现真实登录和服务端权限校验。
6. 当前摄像头画面为诚实占位状态，不是 RTSP 实时流。
7. 当前 Worker 通知失败会保留失败记录，但自动重试调度尚未实现。

## 6. 下一门禁

进入下一批规则前必须完成：

- 配置豆包密钥和真实模型 ID。
- 用一段“开门不足30秒”和一段“开门超过30秒后关闭”的视频运行验收。
- 对照逐帧观察，确认模型能稳定识别目标冰箱门。
- 配置飞书 webhook，验证只发送一次且详情 URL 正确。
- 修复真实联调中发现的问题并补对应回归测试。
