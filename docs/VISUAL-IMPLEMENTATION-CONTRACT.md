# 门店 AI 视频巡检视觉实现契约

> 状态：v1.2
> 参考基线：`prototypes/visual-baseline-v1.2/`；旧版 `visual-baseline-v1/` 保留供差异追溯
> 原则：允许增加缺失功能，不允许无理由改变现有设计语言。

## 1. 视觉优先级

正式实现按以下优先级处理设计冲突：

1. 用户明确确认的原型截图和交互意图。
2. `prototypes/visual-baseline-v1.2/` 中可运行的页面效果。
3. 本视觉契约。
4. `MVP-SCENARIOS-TECHNICAL-DESIGN.md` 中的业务状态和技术约束。

业务状态与原型 Mock 冲突时，保留原型视觉风格，但使用真实业务状态；不得为了迁就 Mock 数据破坏正确业务逻辑。

## 2. 必须继承的整体风格

- 桌面端总部 SaaS，而非移动端或营销落地页。
- 深色左侧导航、白色顶栏、浅灰工作区。
- 内容以白色卡片、细边框、轻阴影组织，不使用厚重渐变或大面积高饱和背景。
- 信息密度保持原型水平：一屏同时看见监控画面、关键指标和最近事件。
- P0/P1/P2 使用稳定且一致的危险色语义，不能仅依靠文字区分。
- 图标统一使用线性 SVG 图标；不得以 emoji 作为正式产品图标。
- 动效克制，仅用于状态变化、任务进度、告警脉冲、抽屉/弹窗和页面切换。

## 3. 基础设计令牌

以下颜色来自原型中的高频值，正式实现应先建立 token，再由组件使用；页面内不得散落新的近似颜色。

| Token | 值 | 用途 |
|---|---|---|
| `--color-bg-app` | `#F8FAFC` | 工作区背景 |
| `--color-bg-surface` | `#FFFFFF` | 卡片、顶栏、弹窗 |
| `--color-text-primary` | `#0F172A` | 标题、核心数据 |
| `--color-text-secondary` | `#64748B` | 描述、辅助信息 |
| `--color-text-muted` | `#94A3B8` | 时间、占位和弱信息 |
| `--color-border` | `#E2E8F0` | 常规边框和分隔线 |
| `--color-primary` | `#4F46E5` | 主操作、选中态 |
| `--color-blue` | `#2563EB` | 分析中、普通信息 |
| `--color-success` | `#059669` | 在线、完成、已解决 |
| `--color-danger` | `#DC2626` | P0、失败、超时 |
| `--color-danger-dark` | `#991B1B` | P0 强调文字 |
| `--color-warning` | `#EA580C` | P1、风险提示 |

字体沿用原型：

```css
font-family: Inter, -apple-system, BlinkMacSystemFont,
  "PingFang SC", "Microsoft YaHei", sans-serif;
```

字号层级保持紧凑：

- 页面标题：20–24px，600–700。
- 卡片标题：15–16px，600。
- 正文和表格：13–14px。
- 标签、时间和辅助信息：11–12px。
- 关键数字允许 26–32px，但必须配合清晰单位或说明。

## 4. 布局契约

### 4.1 应用框架

- 左侧导航固定，深色背景；品牌、门店、一级导航和当前用户的纵向结构保持不变。
- 左侧导航按“总览 / 工具 / 运营”分组；新增的工程化任务与规则入口放入对应组，不破坏原型分组顺序。
- 顶栏固定在主区域顶部，保留页面名称、运行状态、通知和当前门店。
- 主工作区浅灰背景，桌面端默认内容边距 24–28px。
- 首期桌面基线宽度为 1200px 以上；较小视口应出现合理横向适配，而不是挤压关键内容。
- 页面跳转保留原型轻微淡入和 4px 位移，不增加大幅滑动或弹跳。

### 4.2 卡片与容器

- 常规卡片圆角以 8px 为基准。
- 常规边框为 1px `#E2E8F0`。
- 阴影维持原型的轻量级，不使用浮夸悬浮效果。
- 卡片内部信息按“标题—主数据—辅助说明—操作”排列。
- 高危事件用左侧色条、状态标签或浅色危险背景表达，不使用整卡纯红。

### 4.3 密度和对齐

- 同一列表的状态、时间、摄像头和严重度必须纵向对齐。
- 数字使用等宽或稳定宽度，避免实时刷新时跳动。
- 信息过长优先折行或展开，不能简单截断关键异常描述。
- 空状态、加载状态、失败状态和无权限状态占用与真实内容一致的容器区域，避免页面结构跳变。

## 5. 核心页面视觉契约

### 5.1 监控大盘

必须保留：

- 顶部四张指标卡。
- 左侧/中部监控画面矩阵。
- 监控矩阵下方的横向异常事件流（v1.2）；不得回退为右侧窄栏。
- 监控画面可点击进入对应摄像头详情，并可从事件详情返回该摄像头。
- 摄像头在线/离线覆盖层、REC 状态和时间戳。
- 严重度、置信度、门店/区域、发生时间等事件摘要。

允许增加：

- 分析任务状态和模型版本入口。
- “演示模式”标识，避免预置循环视频被误认为真实直播。
- 画面质量异常提示。
- 事件恢复状态。

不得增加会遮挡监控主体的大面积浮层。

### 5.2 上传与分析任务

沿用原型的上传区、摄像头/区域选择、步骤进度和分析结果卡片。真实实现必须补充：

- 文件大小、时长和格式校验。
- 排队、抽帧、分析、聚合、完成、失败和已取消状态。
- 可恢复的任务 ID 和明确失败原因。
- 重试与取消操作。

进度必须来自后端真实状态，禁止用固定定时器模拟。

### 5.3 事件详情

保留原型的证据大图、异常摘要、规则依据、时间线、SLA 和整改操作布局。新增内容优先嵌入既有卡片体系：

- 开始帧、确认帧、峰值帧和恢复帧。
- 原始模型观察与后端规则结论的区分。
- 误报原因。
- 整改前后对照。
- 模型、Prompt 和规则版本追溯信息。

### 5.4 整改跟踪

保留原型筛选栏、状态标签、列表密度和详情交互。业务上使用统一事件状态机，不再创建一套视觉和状态完全重复的“独立工单系统”。如未来确需工单，应在现有事件详情内以关联对象呈现。

### 5.5 摄像头/视频源管理

保持原型卡片和状态样式，首期同时支持：

- 预置演示视频源。
- 上传视频映射的虚拟摄像头来源。
- 后续 RTSP 所需的配置占位，但不伪装为已连接的真实直播能力。

### 5.6 飞书卡片

- 继承原型的标题、门店/摄像头、异常摘要、规则和双操作区结构。
- 卡片必须展示事件 ID，并尽可能携带一张关键证据图。
- P0、P1 和 SLA 升级保持同一信息架构，只调整严重色和动作。
- webhook-only 模式只提供“查看详情”；具备应用回调后再显示状态操作按钮。

## 6. 新增页面规范

原型缺失但 MVP 必需的页面可以创建，但必须复用同一应用框架和组件语言。

### 6.1 组织与账号初始化

- 使用原型中的表格、标签、按钮、弹窗和侧边导航。
- 首次进入采用分步初始化：组织 → 区域/门店 → 账号 → 角色权限 → 完成。
- 不引入完全不同风格的全屏向导。

### 6.2 分析任务页

- 复用上传页的任务步骤样式。
- 列表展示来源、进度、耗时、已分析帧、事件数和失败原因。
- 任务详情使用右侧抽屉或原型风格的详情页。

### 6.3 规则配置页

- 正式规则、实验规则、停用规则明确分组。
- 每条规则显示能力类型、适用区域、确认策略、严重度和通知策略。
- 不允许用户在 MVP 中用自由文本直接创建可执行规则。

### 6.4 审计日志页

- 使用紧凑时间线或表格。
- 支持按事件、操作人、动作类型和时间筛选。
- 模型原始响应默认折叠，避免破坏页面信息密度。

## 7. 动效契约

- 页面进入：约 250ms 淡入并向上 4px，与原型一致。
- 告警脉冲：仅用于新的 P0 或实时 REC 状态，不持续干扰用户。
- 进度动画：反映真实后端阶段；未知进度使用不确定态动画。
- 抽屉/弹窗：150–250ms，使用标准 ease-out。
- 列表更新：保留位置并轻微高亮，不整页闪烁。
- 遵守 `prefers-reduced-motion`。

## 8. 组件复用要求

正式前端至少沉淀以下共享组件：

- `AppShell`、`Sidebar`、`TopHeader`
- `MetricCard`、`SurfaceCard`
- `SeverityBadge`、`StatusBadge`、`ConfidenceChip`
- `CameraTile`、`EventRow`、`EvidenceFrame`
- `AnalysisProgress`、`Timeline`
- `EmptyState`、`ErrorState`、`PermissionState`
- `Drawer`、`Dialog`、`Toast`

同一含义只能有一个正式组件，不允许不同页面分别复制一套近似样式。

## 9. 视觉验收机制

每个页面交付前必须完成：

1. 与原型基线在同一视口截图。
2. 对比整体框架、间距、字体、颜色、圆角、图标和信息密度。
3. 验证默认、加载、空数据、失败、无权限、超时和已完成状态。
4. 检查长中文、英文、数字和时区显示。
5. 检查交互按钮可点击区域、键盘焦点和对比度。

视觉偏差必须作为缺陷处理，而不是在功能完成后再决定是否修复。新增页面由同一视觉令牌和组件库约束，并加入截图回归基线。

## 10. 禁止事项

- 未经确认重做导航、主色或页面信息架构。
- 使用 emoji 代替正式图标。
- 用随机数模拟真实置信度或任务结果。
- 用全新 UI 套件默认主题覆盖原型风格。
- 为了展示“AI 感”增加大面积霓虹、渐变、粒子或无业务意义动画。
- 把技术日志直接堆放在业务主页面。
- 新增页面各自定义颜色、间距和状态名称。
