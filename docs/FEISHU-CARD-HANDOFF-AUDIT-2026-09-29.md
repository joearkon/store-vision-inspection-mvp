## 本轮范围

- 将正式 E1/P1 事件接到企业自建应用机器人发送接口，同时保留原有群 Webhook 作为未配置应用机器人的后备方式。应用机器人优先；应用配置不完整时不误回退。
- 使用现有事件生成卡片，不使用原型的假事件、置信度或 P0 文案。卡片展示门店、摄像头、事件 ID、当前状态、持续时间和整改建议；只保留“查看详情”链接。
- 新增显式测试命令：`python -m scripts.send_feishu_test EVT-0929-81F53E` 本地预览；加 `--send` 才会发送。测试卡片标注“测试·合成视频”，独立幂等键防止重复发送。
- 修复卡片详情 URL，使其指向当前 Web 应用真实的 `/#/event/{id}` 路由；校验飞书 API 的业务 `code`，避免 HTTP 200 被误记为成功；不把可能含 Webhook 密钥的网络异常写入数据库。
- 上传页用户可见文案改为“视觉 AI 分析”。

## 产品逻辑与视觉审计

- A1/B1 等实验规则保持不通知；本轮不会把原型中的 A1/P0 当作真实告警。原型 P0/P1/SLA 三种外观继续作为视觉参考，后端只有 E1/P1 正式通知能力。
- “标记已处理”不进入卡片：需要飞书卡片回调验签、用户绑定、权限和整改证据审计，本轮尚未实现。状态改变仍在 SaaS 内完成。
- 卡片结构继承原型的警示色、摘要、整改建议和底部动作区；当前无公开证据图 URL，不把本地图片地址伪装为可在飞书访问的证据。
- 上传页两处“豆包”品牌字样改为“视觉 AI”。在本地浏览器 `/#/upload` 实际核对了页面说明和分析进度第 4 步，均显示“视觉 AI 分析”；布局与字号未改。卡片本身仅做 JSON dry-run，尚未取得飞书客户端的真实渲染对照。

## 未通过的真实联调门槛

- 截至本审计，`.env` 未配置 `FEISHU_APP_ID`、`FEISHU_APP_SECRET`、`FEISHU_CHAT_ID`；未向飞书发送，因此**不能声称飞书实发成功**。
- 已核对旧项目 `project/inventory-count-closure-demo`：其 Cloudflare Worker 确实配置了同名应用凭据及群机器人 Webhook，且 `wrangler secret list` 只返回密钥名称、不返回值。旧项目的 `notifyFeishu()` 是其自身运营通知通道，不能证明目标为“小茶日记”或直接复用为巡店卡片通道；本轮未改动旧项目、未读取到密钥值、未借其发送。
- 应用机器人需启用并发布可用版本、加入测试群并有消息发送权限。用户需在本地 `.env` 配置凭据和测试群 `chat_id`，不可提交到 Git。
- 用户随后在本地配置了 App ID/Secret。用这组凭据成功取得 `tenant_access_token`；只读查询机器人所在群 `GET /im/v1/chats` 返回 HTTP 400 / `99991672`，响应指出缺少 `im:chat` / `im:chat:read` / `im:chat:readonly` 之一。本轮未擅自申请扩大应用权限。可由用户从“小茶日记”群设置复制以 `oc_` 开头的群 ID，填入 `FEISHU_CHAT_ID` 后继续一次实发。
- 用户提供并配置群 ID 后，对已解决的真实 E1 合成测试事件进行一次实发及一次显式失败重试。两次均未投递，飞书返回 HTTP 400 / `230002`（应用机器人不在目标群）。数据库中测试投递 `NTF-DB3B6F862986` 保留 `failed`、`attempts=2`、无 external message ID；不应称为发送成功。需用户核对该群 ID，并把当前应用机器人加入该群后再试。当前实现最多允许对该失败测试投递显式重试至 3 次。
- 用户随后确认目标群内的是旧加盟商项目使用的**群自定义机器人**，不是当前 App ID 对应的应用机器人。已将当前项目的发送优先级改为：配置群 Webhook 时优先发到该 Webhook；否则才使用应用机器人；Webhook 可选飞书加签 `FEISHU_SIGNING_SECRET`。单元测试验证了双配置时仅调用 Webhook 且附加签名。旧项目的 Cloudflare Secret 仍不可读取；需在群机器人配置中将 Webhook 和加签密钥分别填入本项目 `.env`，实发才可继续。此前 `230002` 不能归因于卡片格式。
- `STORE_VISION_PUBLIC_BASE_URL` 仍指向 `127.0.0.1`。即使测试群收到卡片，“查看详情”也只能在运行该本地站点的同一电脑打开；跨设备闭环需要可访问的 HTTPS 地址及访问控制。
- 应用机器人卡片点击后直接变更整改状态、P0 预警、SLA 升级和卡片更新均未实现，不能按原型显示为可用。
