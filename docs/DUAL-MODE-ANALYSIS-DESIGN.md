# E1 双模式分析设计与 A/B 验证

## 目标

同一条 E1 规则支持两种可选执行模式。分析模式在任务创建时写入 `analysis_runs.analysis_mode`，后续修改默认配置不会改变历史任务，确保结果可追溯、可比较。

## 模式一：逐帧基线 `frame_baseline`

1. FFmpeg 按 1 fps 抽帧；
2. 每帧调用一次豆包视觉观察；
3. 后端将连续 `open` 观察聚合为 E1；
4. 连续达到 30 秒后生成 P1 事件。

该模式是准确性与回归基线。优点是逐秒证据完整，缺点是请求数、Token、延迟随视频时长线性增长。

## 模式二：双层判定 `two_stage`

### 第一层：视频粗筛

- 将 MP4 作为视频输入提交给视觉模型；
- 粗筛 fps 为 0.2；
- 模型只输出疑似开门区间、置信度与可见证据；
- 模型不输出规则结论、严重度或责任判断。

### 第二层：关键时间点复核

对持续时间达到 30 秒的疑似区间，复核：

- 区间起点；
- 区间中点；
- 29、30、31 秒阈值窗口；
- 区间末端；
- 若存在后续画面，再检查恢复点。

复核帧必须与粗筛的开启状态一致。最终 E1 仍由后端代码依据 30 秒阈值确认。

### 自动回退

以下情况自动回退至逐帧基线：

- 视频粗筛调用失败；
- 粗筛画面质量不足；
- 粗筛与局部复核矛盾；
- 缺少阈值确认帧；
- 本地视频超过当前 25 MB 粗筛保护限制。

回退原因写入任务，任务最终仍可完成；实际请求与 Token 必须计入任务统计。

## 配置与页面

- 规则配置页可切换全局默认模式；
- 视频上传页可覆盖本次任务模式，不改变全局默认；
- 分析任务页展示模式、请求次数和 Token；
- 事件详情页展示产生事件的模式和模型消耗；
- 历史任务保留创建时模式快照。

## 真实 A/B 结果

测试视频：`hailuo23-e1-open-50s.mp4`，两次均关闭飞书通知。

| 指标 | 逐帧基线 | 双层判定 | 变化 |
| --- | ---: | ---: | ---: |
| 远程请求 | 50 | 7 | -86.0% |
| Token | 86,553 | 17,130 | -80.2% |
| 分析耗时 | 约 156 秒 | 约 22.5 秒 | -85.6% |
| 基础档估算成本 | ¥0.0775 | ¥0.0148 | -80.9% |
| 首次发现 | 0 秒 | 0 秒 | 一致 |
| 确认异常 | 30 秒 | 30 秒 | 一致 |
| 最后仍开启 | 49 秒 | 49 秒 | 一致 |
| 事件数 | 1 | 1 | 一致 |

双层任务：`RUN-BEA0A30D71D7`；事件：`EVT-0927-D4E401`。

## 当前结论

双层判定已证明能在本测试样本上保持事件结论和关键时间点一致，同时显著降低调用量、Token 与延迟。但它尚不能替代完整验收集。默认模式暂时保持逐帧基线，待以下样本全部通过后再考虑将双层模式设为默认：

1. 开门不足 30 秒；
2. 开门超过 30 秒后关闭；
3. 人员短时遮挡柜门；
4. 玻璃反光但柜门关闭；
5. 画面质量不足或柜门不可见。
